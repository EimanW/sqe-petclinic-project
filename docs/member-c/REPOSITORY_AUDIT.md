| W1. Open an existing owner and submit Add Pet. | `POST /owners/{ownerId}/pets` → `OwnerRestControllerV1.addPetToOwner` (lines 139–155). | `findOwnerById` fetches the Owner, including pets in the active Spring Data JPA query. The controller returns 404 for a missing owner. It maps the request to a new Pet and sets its Owner. Transactional `savePet` resolves the PetType by ID and calls `petRepository.save`. The `pets` row references `owners` and `types`. Source success is 201 with the Pet DTO and a Location path `/api/pets/{id}`. |

| Readback after W1/W2 | `GET /owners/{ownerId}` → `getOwner`. `GET /owners/{ownerId}/pets/{petId}` → `getOwnersPet`. `GET /visits/{visitId}` → `VisitRestControllerV1.getVisit`. | Owner and nested pet reads use `findOwnerById`. ## Rules and test basis gaps

| Rule or gap | Source evidence and needed decision |
| --- | --- |
| Pet age | `PetAgeValidator` accepts the inclusive interval from application-local today minus 50 years through today. It rejects earlier and future dates. Null passes the age validator, while `PetFields` separately requires the birth date. Member B should map the source limits to the approved boundary cases. |
| Pet fields | `PetFields` requires a name, birth date and type. Name is 1–30 characters with at least one non-whitespace character. The service resolves the type ID. Member B should align the approved test basis and verify actual error statuses and UI messages. |
| Visit fields | `VisitFields` requires a date in date format and a description of 1–255 characters with at least one non-whitespace character. No additional scheduling/date-order rule was established. Member B and the team should approve any expectation beyond the schema. |
| Roles | Default security enables Basic, BCrypt/JDBC accounts and method authorization. Owner workflow and direct visit reads require `OWNER_ADMIN`. Vet listing requires `VET_ADMIN`. H2 admin holds both plus `ADMIN`, and vet holds `VET_ADMIN` only. Member A and C should agree on the role matrix, then verify the runtime decisions. CSRF is explicitly disabled and relevant controllers declare `@CrossOrigin`. Browser CORS behavior is pending. |
| Owner–Pet association | Nested reads require the Pet under the Owner. The nested update looks up each record independently. The visit create method uses the supplied Pet reference without consulting `ownerId`. Member A and B should agree on the ownership invariant and missing or mismatched record expectations using OpenAPI and the approved test basis. These are source observations. |
| Duplicates | No explicit duplicate check was located in the W1/W2 create chain or a matching uniqueness constraint in H2 pets/visits. The brief requires repeated-request duplicate coverage. Member B should lead approval of duplicate identity, retry behavior and expected response per operation, with A and C reviewing. |
| State transition and compound rule | The model exposes no scheduled/completed/cancelled Visit lifecycle. All members need to agree on a defensible, source-grounded transition with allowed and rejected states and a compound decision with at least two Boolean conditions. Ask the instructor if the proposed transition’s eligibility is unclear. Record approved criteria before implementing related assertions. |
