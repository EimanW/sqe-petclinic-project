# Goal–Question–Metric definitions

**Proposed · 2026-11-28.** C maintains the weekly metrics. B validates defect and traceability inputs. A reviews the production scope and agrees targets through the shared test plan. Apply one consistent Asia/Karachi reporting cutoff and record the source revision and data export date each week.

| Metric | Goal and question | Formula, population and unit | Source, cadence and owner | Interpretation, proposed target and limitations |
| --- | --- | --- | --- | --- |
| Defect density | Identify where W1/W2 production code requires deeper testing. How many confirmed defects were first verified in the reporting period per size of the agreed code scope? | Unique confirmed in-scope defects first verified in the period ÷ (relevant production source lines ÷ 1,000). Numerator includes confirmed defect IDs once, with duplicates and out-of-scope items excluded. Denominator is the agreed W1/W2 production code manifest on the measured revisions. Unit is defects per production KLOC. | B's defect log and linked confirmed issues. A/C agree the exact backend/Angular production paths, versioned commits and OSS LOC tool/version, such as cloc. Exclude test, generated, vendor, blank and comment lines. Review weekly, with B validating IDs and C recording the value. | Trends reflect discovery effort and scope changes. Compare only equivalent manifests and periods, report uncovered ecosystems or omitted shared code, and avoid mixing defect scope with a different LOC scope. Baseline first. Target pending team agreement. |
| Requirements coverage, mapped | Make scope gaps visible before testing. How many approved functional requirements have at least one mapped executable case? | Unique approved in-scope W1/W2 requirement IDs with an executable case mapped ÷ all approved in-scope W1/W2 requirement IDs × 100. Unit is percent. | B's versioned matrix and case inventory, reviewed weekly. B validates IDs and C reports with breakdown per workflow and test level where useful. | A mapped case shows a link. Report missing required levels, flows and rule combinations separately. Proposed 100% mapped by agreed implementation exit. |
| Requirements coverage, successfully executed | Understand demonstrated requirements coverage. How many approved requirements have successful evidence for all required cases on the reporting baseline? | Unique approved W1/W2 requirement IDs for which all required mapped cases were executed and passed on the approved baseline ÷ all approved in-scope W1/W2 requirement IDs × 100. Unit is percent. Missing, failed, skipped or stale evidence leaves a requirement uncovered. | B's matrix and original test results on the reporting baseline, with approved case sets and target revisions. B checks coverage and C reports weekly. | A missing case mapping or unresolved test basis limits this measure. Proposed 100% for agreed critical requirements at release, with overall target pending. Show mapped and passed separately. |
| Defect reopen rate | Evaluate closure quality. How often do confirmed in-scope defects closed in the reporting period reopen before that period ends? | Unique confirmed in-scope defects first closed during the period and reopened after that closure by period end ÷ unique confirmed in-scope defects first closed during that same period × 100. Count each eligible ID once and use the same closure and reopen definitions each week. Unit is percent. | B's issue status/event history with closure and reopen timestamps, checked at each cutoff. B validates transitions and C reports. | Short periods can hide later reopens. Record late reopens of earlier cohorts separately, and keep cohort membership and cutoff stable. Baseline first. Target pending team agreement. |

Separate **NOT MEASURED** for missing or unvalidated inputs from **N/A** when a known denominator is zero. A measured 0% requires a positive denominator and verified zero numerator. Keep numerator, denominator, value, scope/version, interpretation and linked evidence in each report. A repeated issue ID or case ID only contributes once to the relevant count.
